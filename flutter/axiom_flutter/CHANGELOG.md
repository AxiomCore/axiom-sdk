## 0.150.0 - 2026-11-21

Runtime parity release. Code generated by `axiom_flutter_generator` 0.146.x
still compiles. Regenerate with 0.150.0 to get the fixes below.

Added
- Android support: bundled `libaxiom_runtime.so` for arm64-v8a, armeabi-v7a
  and x86_64 (minSdk 24). The cache defaults to the app support directory.
- `AxiomRuntime.initialize(config)`: one call loads every contract, checks the
  runtime ABI, data ABI and contract reader versions, and returns an
  `AxiomInitResult` with a per-contract `AxiomContractLoadResult`. A second
  call returns the first result. `AxiomVersionMismatch` when the binary and
  the package do not match.
- Hash-locked contract loads (`AxiomContractConfig.sha256`) and
  `AxiomConfig.requireSignedContracts`. `AxiomContractTrust` reports
  unsigned, signed or locked.
- `AxiomCallOptions` per call: `timeout`, extra `headers`, and
  `cacheMode: AxiomCacheMode.refresh` to skip the cache.
- Cancellation: `AxiomRuntime.cancel`, `AxiomQuery.cancel()`, `Cancelled`
  error code and `AxiomError.isCancelled`. A query's request is cancelled when
  its last listener leaves.
- Session control: `resetSession()` (logout) and `shutdown()` (allows a new
  `initialize`, for hot restart).
- Auth: `setNamespaceAuthToken`, `setGlobalAuthToken` and their `clear...`
  methods; `setAuthProvider` for token refresh.
- Cache control: `invalidate`, `clearCache`, `purgeCache`, `setQueryData`,
  `getCachedQueryData`, `AxiomQuery.refresh(force: true)`.
- `onError`: one stream with every error of every call (cancellations
  excluded).
- Typed failures: `AxiomError.failureCode`, `failurePayload`, `failure()`
  and `AxiomFailureRegistry`.
- `AxiomChannel` with `AxiomReconnectPolicy` and `openChannel` for WebSocket
  endpoints.
- `AxiomEnvironment` and `AxiomConfig.baseUrlOverrides`;
  `--dart-define=AXIOM_ENV` / `AXIOM_BASE_URL`.
- Extensions on Android, iOS and macOS: `loadExtension`, `invokeExtension`,
  `extensionLifecycle`, `extensionAudit`. Web throws `UnsupportedError`.
- `AxiomRuntime.runtimeInfo` (`AxiomRuntimeInfo`).
- iOS and macOS privacy manifest.
- Example app in `example/`.

Fixed
- Request bodies with several fields are sent as one JSON object; a single
  body parameter is sent as a raw JSON value (fixed in the generator).
- Bytes fields are base64 on the wire in both directions.
- Header parameters are sent as HTTP headers, not only used as cache keys.
- SSE and NDJSON frames are decoded per frame instead of as one JSON value.
- Web: `cache_first` and `stale_while_revalidate` return the cached value on
  the second call.
- Web: the wasm runtime is loaded without `eval`, so it works under a strict
  Content Security Policy and with a `--base-href`.
- Web: response buffers are freed after each call.
- iOS and macOS: the runtime archive is pinned by SHA-256 in
  `runtime-pin.json`; a failed check keeps the previous framework and stops
  the build.
- Cancel errors (plain text from the runtime) no longer fail JSON parsing.
