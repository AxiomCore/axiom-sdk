## 0.150.1 - 2026-11-21

Size and speed release. Code generated by `axiom_flutter_generator` 0.150.0
keeps working; regenerate with 0.150.1 for the faster model decoders.

Changed (behaviour changes first)
- **Behaviour change:** on Android and the web the package bundles the lean
  runtime, built without executable extensions and without the telemetry
  exporter. Queries, mutations, streams, auth, cache and cancellation are
  unchanged. The four extension methods (`loadExtension`, `invokeExtension`,
  `extensionLifecycle`, `extensionAudit`) now throw an error that names
  `axiom_flutter_extensions`. To keep extensions on Android, add
  `axiom_flutter_extensions: ^0.150.1`. iOS and macOS still use the full
  published AxiomRuntime 0.148.6.
  <!-- VERIFY: /home/node/fp/pack/REPORT.md (lean default, error text, add-on name) -->
- Android app builds no longer contain the web runtime (`axiom_runtime_bg.wasm`
  and its JS glue), which Android never loads: an arm64 release APK of the
  integration app is 957 KB smaller. Set `axiom.keepWebAssets=true` in
  `android/gradle.properties` to keep the files.
- Responses of endpoints without field validators get a JSON syntax check
  instead of a full parse into a tree. Valid and invalid bodies are accepted
  and rejected exactly as before, with the same error codes.

Fixed
- Response decoding no longer re-encodes the body to look for SSE framing,
  and the Dart VM decodes JSON straight from the response bytes.
- The response body is handed from the runtime to Dart without an extra copy.

Added
- `doc/usage.md`: the end-to-end steps from contract to first query.

Known limits
- iOS and macOS keep the full runtime 0.148.6 until the next Apple runtime
  release; the lean runtime and the size savings apply to Android and web only.
- WebSocket channels on iOS and macOS still need the next Apple runtime.
- Flutter 3.32 has no per-platform assets: iOS and macOS bundles still carry
  the unused web wasm.

## 0.150.0 - 2026-11-21

Runtime parity release. Code generated by `axiom_flutter_generator` 0.146.x
still compiles. Regenerate with 0.150.0 to get the fixes below.

Qualification suite results for this release: web debug 88 pass / 8 fail /
31 skip; web release with `--base-href` and a strict CSP 88/8/31 with no CSP
violation; dart2wasm 89/7/31; macOS host and iOS simulator 81/3/34 with the
published AxiomRuntime 0.148.6 (the 3 failures are the WebSocket checks).
The Android emulator (arm64, API 36) passes.

Added
- Android support: bundled `libaxiom_runtime.so` for arm64-v8a, armeabi-v7a
  and x86_64 (minSdk 24). The cache defaults to the app support directory.
- `AxiomRuntime.initialize(config)`: one call loads every contract, checks the
  runtime ABI, data ABI and contract reader versions, and returns an
  `AxiomInitResult` with a per-contract `AxiomContractLoadResult`. A second
  call returns the first result. `AxiomVersionMismatch` when the binary and
  the package do not match.
- Hash-locked contract loads (`AxiomContractConfig.sha256`) and
  `AxiomConfig.requireSignedContracts`. `AxiomContractTrust` reports
  unsigned, signed or locked.
- `AxiomCallOptions` per call: `timeout`, extra `headers`, and
  `cacheMode: AxiomCacheMode.refresh` to skip the cache.
- Cancellation: `AxiomRuntime.cancel`, `AxiomQuery.cancel()`, `Cancelled`
  error code and `AxiomError.isCancelled`. A query's request is cancelled when
  its last listener leaves.
- Session control: `resetSession()` (logout) and `shutdown()` (allows a new
  `initialize`, for hot restart).
- Auth: `setNamespaceAuthToken`, `setGlobalAuthToken` and their `clear...`
  methods; `setAuthProvider` for token refresh.
- Cache control: `invalidate`, `clearCache`, `purgeCache`, `setQueryData`,
  `getCachedQueryData`, `AxiomQuery.refresh(force: true)`.
- `onError`: one stream with every error of every call (cancellations
  excluded).
- Typed failures: `AxiomError.failureCode`, `failurePayload`, `failure()`
  and `AxiomFailureRegistry`.
- `AxiomChannel` with `AxiomReconnectPolicy` and `openChannel` for WebSocket
  endpoints.
- `AxiomEnvironment` and `AxiomConfig.baseUrlOverrides`;
  `--dart-define=AXIOM_ENV` / `AXIOM_BASE_URL`.
- Extensions on Android, iOS and macOS: `loadExtension`, `invokeExtension`,
  `extensionLifecycle`, `extensionAudit`. Web throws `UnsupportedError`.
- `AxiomRuntime.runtimeInfo` (`AxiomRuntimeInfo`).
- iOS and macOS privacy manifest.
- Example app in `example/`.

Fixed
- Request bodies with several fields are sent as one JSON object; a single
  body parameter is sent as a raw JSON value (fixed in the generator).
- Bytes fields are base64 on the wire in both directions.
- Header parameters are sent as HTTP headers, not only used as cache keys.
- SSE and NDJSON frames are decoded per frame instead of as one JSON value.
- Web: `cache_first` and `stale_while_revalidate` return the cached value on
  the second call.
- Web: the wasm runtime is loaded without `eval`, so it works under a strict
  Content Security Policy and with a `--base-href`.
- Web: response buffers are freed after each call.
- iOS and macOS: the runtime archive is pinned by SHA-256 in
  `runtime-pin.json`; a failed check keeps the previous framework and stops
  the build.
- Cancel errors (plain text from the runtime) no longer fail JSON parsing.
- iOS and macOS: the podspecs carried a wrong digest for the published
  AxiomRuntime 0.148.6 archive, so `pod install` failed; both now read the
  correct pin.
- Native cache: a default database path (app support directory) is passed to
  the runtime, so `cache_first` and `stale_while_revalidate` work on Android,
  iOS and macOS without configuration.
- Native call latency: the response pump runs only while requests are in
  flight and wakes per response (p50 of a local call 95.8 ms -> 2.6 ms on a
  Linux host). It tracks in-flight request ids instead of a counter, so a
  late response cannot stop it early.
- SSE on native and web: one shared parser that decodes UTF-8 incrementally
  and joins CRLF pairs split across chunks.
- Android 32-bit (armeabi-v7a): `size_t` fields of FFI structs use `@Size()`,
  fixing the struct layout that corrupted calls on 32-bit ARM.
- An empty 2xx response body completes the call with success instead of
  hanging or failing to parse (see Known limits for typed endpoints).
- The query key includes request headers and the timeout, so two calls that
  differ only in headers no longer share a cached result.
- Explicit tokens are sent as `Authorization: Bearer`, and a namespace token
  is sent only to its namespace (global token as fallback).
- Cancelling a request that has just been issued is reliable on Android.
- A failed `initialize` can be retried; the status of `axiom_initialize` is
  checked.
- Web: responses are delivered on a runtime notification instead of a 16 ms
  polling floor; WebSocket send works.

Breaking changes
- Android is a new platform and needs `minSdk 24`. iOS 13.0 and macOS 11.0
  remain the minimum deployment targets; `axiom pull --fix` sets them.
- Generated enums gain an `unknown` value (from generator 0.150.0), so an
  exhaustive `switch` over a generated enum must handle it. Unknown wire
  values no longer throw on decode.
- `AxiomAuthBinding.attach` in `axiom_flutter_auth` 0.150.0 takes a required
  `namespaces` list.

Known limits
- WebSocket channels on iOS and macOS need the next AxiomRuntime release; with
  the pinned 0.148.6 runtime the three WebSocket checks fail (81 of 84 run
  checks pass on the macOS host and the iOS simulator). The error names the
  cause. Android and web are not affected.
- Web: a browser cannot send `Authorization` on a WebSocket upgrade, so
  WebSocket endpoints on web need cookie sessions.
- An empty body (for example `204 No Content`) on an endpoint that declares a
  typed response is rejected by the current runtime; the SDK side is fixed
  and the runtime fix ships with the next runtime release.
- Dart 3.8.0 / Flutter 3.32.0 compiler issue (not in this package): a release
  web build (dart2js) crashes with "Null check operator used on a null value"
  in any `async` function named `result`. Rename the function.
- Web (dart2js): `int` above 2^53 loses precision; use string fields for
  64-bit identifiers. dart2wasm and native builds are not affected.
- The web runtime (wasm, about 0.96 MB) is also bundled in Android, iOS and
  macOS builds, because Flutter 3.32 has no per-platform assets. See
  `doc/wasm-size.md` for the app-side opt-out.
- Contract variants: CLI 0.156.0 cannot build a managed backend variant that
  leaves out endpoints; `--variant` is passed through but not covered by a run.
